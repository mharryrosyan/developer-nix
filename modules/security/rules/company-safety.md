# Corporate AI Security & Safety Guardrails

This policy is automatically enforced across all AI Coding Agents (Antigravity, OpenCode, Kiro-CLI, OpenClaw, Hermes Agent) for all engineers.

## 1. Data Privacy & Customer Protection (Zero PII Tolerance)
- **STRICTLY PROHIBITED:** Passing any real customer data, personally identifiable information (PII), National ID (NIK), credit card numbers, phone numbers, or customer transaction history into LLM prompts or external APIs.
- When testing or reproducing bugs, engineers and AI agents must **ONLY use sanitized, synthetic, or mocked data**.
- Never instruct an agent to query production databases containing customer records.

## 2. Credentials & Secret Management
- **NEVER** expose, upload, or paste plain credentials, passwords, private keys (`*.pem`, `id_rsa*`), or cloud service tokens (`AWS_*`, `GCP_*`, `GITLAB_TOKEN`, `JIRA_API_TOKEN`) into chats or LLM context.
- All secrets must be referenced via environment variables loaded from `~/.config/company-ai/secrets.env` or local secret managers.
- Any attempt by an AI tool to dump or read `secrets.env` or `*.env` files must be rejected immediately.

## 3. Sandboxing & Safe Tool Execution
- MCP Database tools (`dbx`) are restricted to **read-only queries on local/staging environments**. Modifying production data via AI is strictly forbidden.
- Shell execution permissions (`rm -rf`, destructive migrations, git force push) must always be reviewed manually by the engineer before execution.
- All code generated by AI must adhere to company linting, testing, and security review standards before being committed to GitLab.
